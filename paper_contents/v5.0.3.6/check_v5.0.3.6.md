# 检查：v5.0.3.6 EQ 上「贪心 J_C ≈ 0，但 5M 测试未通过率 14.7%」

- 检查日期：2026-10-14；对象：v5.0.3.6（commit 46caadd）EQ 的 PPO（5d6f2706）与 DQN（37fc5532），GT DQN（15003b19）与 LT PPO（cb432d64）作对照。
- 只读已有 checkpoint / 日志，CPU 确定性回放；脚本 `paper_contents/v5.0.3.6/check_v5.0.3.6.py`（参数：场景 算法目录 exp_id learner）。
- 不涉及新训练、不定版本号。

## 1. 问题

EQ 上 PPO 的 λ 在 4M 前降到 0；最后一次 λ 更新（5.01M 步）的贪心 J_C = 0.00（100 局），但 5M 报告中测试集未通过率 14.7%、训练集 13.0%。两者不一致。DQN EQ 同样：最后几次贪心 J_C 0–0.07，5M 测试未通过率 24.0%。

## 2. 排除评估误差：最终模型在任何数据和 λ 观测下都违约

每个模型用它训练时的 λ（ckpt_lambda.json / final_lambda）。「池随机 500」= 与训练中贪心 J_C 相同的抽样方式（5 万实例池随机抽取）。

| 模型 | λ | 池随机 500：J_C / 违约局 | 训练 1600：J_C / 违约局 | 测试 400：J_C / 违约局 |
|---|---|---|---|---|
| PPO EQ 3M | 0.641 | 0.002 / 0.2% | 0.003 / 0.3% | 0.000 / 0.0% |
| PPO EQ 4M | 0.000 | 0.006 / 0.2% | 0.008 / 0.4% | 0.000 / 0.0% |
| PPO EQ 最终 | 0.000 | 0.200 / 14.4% | 0.167 / 13.0% | 0.188 / 14.7% |
| DQN EQ 3M | 0.000 | 0.002 / 0.2% | 0.001 / 0.1% | 0.003 / 0.3% |
| DQN EQ 4M | 0.066 | 0.024 / 2.4% | 0.030 / 2.6% | 0.045 / 4.5% |
| DQN EQ 最终 | 0.101 | 0.186 / 18.6% | 0.214 / 21.0% | 0.240 / 24.0% |

- 把观测中的 λ 改成 0.5 或 2.0，PPO 最终模型的测试违约局仍是 14.5–15.0%：违约不是 λ 观测不一致造成的。
- 训练进程结束时在 GPU 上直接用内存中的模型评估（results.json）：PPO 隐私违约 13.5%、DQN 24.0%，与从文件加载后 CPU 评估一致：保存 / 加载 / 设备无误。
- 结论：**评估没有问题，最终模型本身就违约；违约出现在 4M 之后，而且是训练最后极短的一段内。**

## 3. 违约在最后一段突然出现

训练曲线中行为策略每 10k 步的违约局比例（4.9M 之后）：

| 运行 | 4.90M | 4.93M | 4.94M | 4.96M | 4.98M | 4.99M | 5.00M | 5.01M |
|---|---|---|---|---|---|---|---|---|
| PPO EQ（随机采样） | 0.1% | 0.1% | 0.5% | 0.1% | 0.1% | 0.0% | 0.3% | 0.5% |
| DQN EQ（ε = 0） | 1.8% | 0.3% | 2.0% | 3.4% | 1.0% | 7.7% | — | — |
| DQN GT（ε = 0） | 0.2% | 4.9% | 16.7% | 14.1% | 14.3% | 3.4% | — | — |
| PPO LT（随机采样） | 8.7% | 11.8% | 12.0% | 7.6% | 7.2% | 5.9% | 5.5% | 6.0% |

- **DQN**：ε 在 2M 后为 0，行为策略就是贪心策略。违约率在 1 万步内能从 0.2% 跳到 16.7% 再回落，说明策略本身在快速振荡；最终模型正好落在 EQ 的上升段（最后 10k 步 7.7%，最终 18.6%）。
- **PPO**：最后一次贪心 J_C（5.01M，更新前的策略）为 0，而 PPO 在最后一次 rollout（到 5,017,600 步）之后还做了一次梯度更新，保存的是更新后的策略。行为策略（随机采样）一直约 0.3%，但确定性策略在这一次更新后违约 14%。**推断**：λ = 0 时奖励里没有任何违约惩罚，违约动作与合法动作的 logits 接近持平（违约动作 AR 往往更高），一次更新就足以翻转大量实例上的 argmax。此推断与数据一致，但没有更新前一刻的模型可直接对照。

## 4. 原因

1. λ 降到 0 不是平衡，而是「惩罚消失」：EQ/GT 上贪心 J_C 多数为 0（100 局分辨率 0.01），归一化更新每次 −η，λ 很快降到 0。
2. λ = 0 后，策略缺少远离违约的梯度，违约动作只靠先前学到的偏好压住，逐渐与合法动作持平。
3. 违约回升后，λ 要以 +0.025/1000 局的速度从 0 重新涨起来，比策略变坏慢得多（DQN 1 万步内即可变坏）。
4. 只在训练终点取一个快照评估，结果取决于终点恰好落在振荡的哪个相位：PPO GT 末端为 0%，EQ 为 14.7%。

## 5. 对 20M 的含义

- 20M 时 EQ/GT 处于 λ ≈ 0 的时间更长，同样的终点翻转可能更频繁；20M 单快照的违约率不可靠。
- 这不是评估代码问题，不需要修评估；需要处理的是 λ ≈ 0 时的约束失效和终点快照的随机性。
- 可直接针对的方向（待用户决定）：
  - λ 设下限（如 λ_min = 0.1–0.5，EQ/GT 上 λ 原本就在 0–0.3 振荡），使违约永远有代价；
  - 增大贪心 J_C 的局数（100 → 1000），分辨率 0.001，与 d = 0.001 同量级，避免「J_C = 0 → λ 只降不升」；
  - 降低 λ 下降速度（下降用更小的 η，非对称更新）。
