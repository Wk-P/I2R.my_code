# v4.3.4 — 冲突感知观测（Conflict-Aware State Ablation）

新的次版本（tag `v4.3.4`）。

## 1. 动机

- 贪心基线与 v4.3.3 的 best-of-K 显示：RL 在 LT 上明显提高成功率，但在成功解的 AR 上与启发式相当；EQ/GT 上同样耗时下随机贪心的 AR 更高。
- v4.3.1.x 的观测（87 / 77 / 102 维）不含服务之间的冲突关系。冲突对的概率 p = 0.6，LT 约 63/105、EQ/GT 约 27/45 个服务对互相冲突；AR 的优化很大程度上是"如何给冲突图分组"，ILP 拿到完整冲突图，RL 只看到压缩后的摘要（当前服务与各 ECU 是否冲突、各 ECU 还能接纳的服务比例、每个剩余服务的可行 ECU 比例）。
- 两个实例可能当前观测相同、未来冲突结构不同、最优动作不同，问题实际上是 POMDP。本版本检验：**原始冲突信息的缺失是否限制了 RL 的策略质量。**

## 2. 改动（唯一变量：观测）

- `src/paper_rl/env.py`：新增 `obs_mode`（`base` = v4.3.3 及以前的观测，`conflict` = 本版本）。`conflict` 在原观测末尾追加尚未放置的服务之间的冲突图：按放置顺序的上三角，固定长度 M(M−1)/2（LT 105 维，EQ/GT 45 维），一对服务互相冲突且都未放置（含当前服务）时为 1，否则为 0。不做任何人工特征（冲突度、阻塞分数等），也不含任何启发式的选择。
- 原观测部分逐步完全不变（已在三个场景各 30 个实例的每一步上核对）；动作掩码在观测中的位置不变（MaskableDQN 依赖它）。
- `src/paper_rl/train.py`：新增 `--obs {base, conflict}`（默认 `base`，与旧版一致），写入 `results.json` 的 `obs` 字段；评估日志改为输出成功实例上的 AR、ILP AR、AR gap。
- 其余与 v4.3.1.6 完全相同：shared base reward（legacy）、12 个模型、超参、5M 步、种子 1–3、数据与划分、评估方式（每个测试实例 1 次确定性输出）。
- `src/scripts/run_v4.3.4.py`：108 个任务；报告对比「原观测」（v4.3.1.6，v4.3.1.7 重评）、「冲突观测」（本版本）与贪心。

## 3. 启动安排

v4.3.1.10（10M）跑完后再启动，独占机器。代码在 v4.3.1.10 运行期间以补丁形式保存（`src/scripts/pending/v4.3.4_obs_conflict.patch`），以保证 v4.3.1.10 的全部任务都运行在它自己的提交上；`src/scripts/pending/after_v4.3.1.10.sh` 在 v4.3.1.10 结束后应用补丁、提交并打 tag、重新生成 v4.3.1.10 报告，然后启动本版本。
