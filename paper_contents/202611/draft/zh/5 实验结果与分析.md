# 5 实验结果与分析（中文对照版）

> 本文件是英文正文 `../5 Experimental Results and Analysis.md` 的中文对照，供核对内容。以英文版为准，修改时两边同步。

本章把 12 个算法–策略变体与 ILP 最优解进行比较。5.1 节介绍实验设置；5.2 节定义评价指标；5.3 节比较解的质量、约束满足情况和计算时间；5.4 节按部署场景分析结果；5.5 节讨论结论和局限。

## 5.1 实验设置

**场景与实例。** 考虑服务数与 ECU 数比例不同的三个部署场景：LT（$N = 10$，$M = 15$；ECU 少于服务）、EQ（$N = 10$，$M = 10$）、GT（$N = 15$，$M = 10$；ECU 多于服务）。ECU 容量从 $\{50, 55, \dots, 195\}$ 均匀抽取，服务需求从 $\{10, 15, \dots, 95\}$ 均匀抽取。共 $K = 10$ 个隐私冲突集，任意两个服务冲突的概率为 $p = 0.6$。每个场景生成 50,000 个训练实例和固定的 5,000 个测试实例，两者互不重叠。每个实例都用 3.2 节的 ILP 求到最优，所以所有实例都已知可行，且每个测试实例都有 $\text{AR}_{\text{ILP}}$。所有方法共用同一测试集。

**训练。** 每个回合开始时从训练池中随机抽一个实例。所有变体都使用 4.1 节的策略网络，训练 $2 \times 10^7$ 个环境步，$\gamma = 1$，回合不提前结束，使用 3 个随机种子（1、2、3）。共训练 108 个 run（12 个变体 × 3 个场景 × 3 个种子）。超参数见表 5.1。

**表 5.1** 训练超参数。

| | PPO | DQN / DDQN |
|---|---|---|
| 并行环境数 | 40 | 12 |
| 学习率（Adam，恒定） | $3\times10^{-4}$ | $10^{-3}$ |
| 批量 | 每次更新 20,480 步，minibatch 256 | 回放池 100k，batch 64 |
| 更新 | 10 个 epoch（PPO-M 为 6） | 每 48 条新转移做 1 次梯度更新 |
| 其他 | GAE 0.95，clip 0.1，熵系数 0.005，价值系数 0.5 | $\varepsilon$ 在前 $2\times10^6$ 步内从 1 线性降到 0；目标网络约每 492 步硬同步 |
| Lagrangian | $\lambda_0 = 0.001$，Adam lr 0.035，$d = 0.001$；每个 rollout 更新 | 同左；每 1000 个回合更新 |

**基准与环境。** ILP 基准使用 Dinkelbach 方法（容差 $10^{-6}$），PuLP + CBC 单线程求解。实现使用 Python 3.12、PyTorch 2.5.1、Stable-Baselines3 / sb3-contrib 2.7.1、Gymnasium 1.2.3。训练在 NVIDIA GTX 1080 Ti 上进行，所有计时在 Intel Xeon E5-2660 v4 CPU 上测得。

## 5.2 评价指标

每个训练好的模型在其场景的 5,000 个测试实例上做确定性推理：每一步选分数最高的动作。结果先对 3 个种子取平均，± 表示种子间标准差。除非另有说明，变体的报告值为三个场景的算术平均。

**最优性差距。** 记 $\mathcal{T}$ 为测试集。AR 只计合法部署（4.2.3 节），失败的回合也计入平均。报告

$$
\text{绝对 gap} = \overline{\text{AR}_{\text{ILP}}} - \overline{\text{AR}},\qquad
\text{相对 gap} = 1 - \frac{\frac{1}{|\mathcal{T}|}\sum_{i \in \mathcal{T}} \text{AR}^{(i)}}{\frac{1}{|\mathcal{T}|}\sum_{i \in \mathcal{T}} \text{AR}^{(i)}_{\text{ILP}}}.
$$

除非另有说明，"gap"指相对 gap。

**约束违约。** 容量违约率和隐私违约率分别为至少出现一次该类违约的测试实例所占比例：

$$
\text{容量违约率} = \frac{1}{|\mathcal{T}|}\sum_{i} \mathbb{1}\Big[\textstyle\sum_t v^{\text{cap}(i)}_t > 0\Big],\qquad
\text{隐私违约率} = \frac{1}{|\mathcal{T}|}\sum_{i} \mathbb{1}\Big[\textstyle\sum_t v^{\text{priv}(i)}_t > 0\Big].
$$

两类违约可能出现在同一实例中，所以总违约率不超过两者之和。对动作掩码，还报告 *EXIT 率*，即在死局处以 EXIT 结束的实例比例。

**计算时间。** 3 × 5,000 个测试实例在单个 CPU 线程上逐个计时。ILP 时间包括建模和全部 Dinkelbach 迭代。RL 时间为一个完整的确定性回合，包括 reset、计算掩码、前向推理和环境 step，使用每个变体种子 1 的模型。加速比 = ILP 平均时间 / RL 平均时间。

**解的质量。** 表 5.2 把 12 个变体与 ILP 最优值进行比较。

**约束处理策略的比较。** 表 5.3 按策略和算法重新排列同样的 gap。

**表 5.3** 按策略与算法的相对 gap（每列最好值加粗）。

| 策略 \ 算法 | PPO | DQN | DDQN | 行平均 |
|---|---|---|---|---|
| 不约束 | 6.12% | 24.97% | 22.59% | 17.90% |
| Lagrangian | 6.24% | 12.51% | 13.84% | 10.86% |
| 动作掩码 | **4.38%** | 7.17% | **6.44%** | **6.00%** |
| 动作修复 | 7.15% | **6.50%** | 7.37% | 7.01% |
| 列平均 | 5.97% | 12.79% | 12.56% | 10.44% |

平均来看，策略排序为掩码（6.00%）< 修复（7.01%）< Lagrangian（10.86%）< 不约束（17.90%）。两种硬策略（掩码、修复）直接作用于动作本身，明显优于只通过奖励起作用的两种软策略。差别在基于值函数的算法上最大：对 DQN 和 DDQN，硬策略把 gap 降低约 5 到 18 个百分点。PPO 对策略不敏感得多，四种策略下都在 4.4% 到 7.2% 之间，PPO-U（6.12%）和 PPO-L（6.24%）甚至略优于 PPO-R（7.15%）。掩码是 PPO 和 DDQN 的最好策略，而 DQN 用修复（6.50%）略好于掩码（7.17%），这一例外的原因尚未查明。

**约束满足。** 表 5.4 给出平均违约率。

**表 5.4** 违约率（容量或隐私），三个场景平均。

| 策略 \ 算法 | PPO | DQN | DDQN |
|---|---|---|---|
| 不约束 | 0.75% | 30.44% | 33.89% |
| Lagrangian | 0.64% | 1.20% | 2.11% |
| 动作掩码 | 0.00% | 0.00% | 0.00% |
| 动作修复 | 0.85% | 1.88% | 2.20% |

只有动作掩码在每个测试实例上都同时满足两类约束，符合"隐私是硬约束"的要求；它唯一的失败形式是在死局处 EXIT（5.4 节）。修复只在死局处违约，因为那时没有可行 ECU 可供替换。Lagrangian 策略把违约压得较低（0.6–2.1%），但到 $2\times10^7$ 步时期望代价仍未降到预算 $d = 0.001$。不做约束处理时，DQN 和 DDQN 学不会约束，约三分之一的实例至少违约一次；相比之下，PPO-U 只有 0.75% 的实例违约，说明 PPO 仅凭稀疏的失败奖励就能学到大部分约束。违约部署不计入 AR，所以非掩码变体的 gap 已经包含了违约造成的 AR 损失；但这些变体是在允许违约的条件下得到的，其 gap 与掩码的 gap 并不严格可比。

## 5.5 讨论

**主要结论。** 动作掩码 + PPO + 关系感知 Transformer（PPO-M）得到的策略从不违反容量或隐私约束，平均最优性差距 4.38%，求解速度比 ILP 快 28×（最大场景上 47.5×）。在策略方面，只有动作掩码能保证约束；修复只在死局处失败；Lagrangian 和不约束策略通过奖励逐步减少违约，与基于值函数的算法配合很差。在算法方面，PPO 在所有策略下都表现稳定，而 DQN 和 DDQN 只在硬策略下有竞争力。剩余的 gap 大多集中在服务多于 ECU 的场景。

**为什么硬策略有助于基于值函数的学习。** 在软策略下，违约只影响回报，在不约束策略下更是只影响终局回报。DQN 和 DDQN 必须通过自举目标把稀疏、延迟的信号传回造成违约的那一步，而回放池中还混有旧惩罚权重下收集的转移。掩码和修复把不可行动作从执行中去掉，掩码还把它们从 TD 目标中去掉，值函数只需要对可行动作排序。PPO 的 on-policy 更新加上接近蒙特卡洛的优势估计（$\gamma = 1$，GAE 0.95），似乎能更稳健地处理稀疏的终局惩罚。

**离线设计成本与在线成本。** Safe RL 方法所需的设计工作并不比 ILP 少：MDP、奖励、约束处理策略、网络和超参数都要设计，每个 run 还要训练 $2\times10^7$ 步。但这些成本是一次性的、在离线完成。在线时，训练好的策略每个实例只需 $M$ 次前向推理，代价是 $N$、$M$ 的多项式，且与实例难度无关；而精确求解这个强 NP-hard 问题，在每一轮 Dinkelbach 迭代中都有最坏指数级的代价。记 $T_{\text{ILP}}$、$T_{\text{RL}}$ 为单实例时间，$C_{\text{train}}$ 为训练成本，则实例数 $I > C_{\text{train}} / (T_{\text{ILP}} - T_{\text{RL}})$ 后 RL 的总成本更低，问题规模越大，这个盈亏点越靠前。按本机实测（3 个 run 共用一张 GTX 1080 Ti），PPO-M 每个 run 的训练耗时为 LT 3.6 h、EQ 3.2 h、GT 3.6 h。代入表 5.5 的单实例时间，单个 PPO-M 模型的盈亏点约为 LT $1.3\times10^4\,\text{s} / 3.22\,\text{s} \approx 4.1\times10^3$ 个实例、EQ $2.5\times10^4$ 个、GT $2.0\times10^4$ 个，即 ILP 越慢的场景，训练成本回收得越快。这里比较的是 GPU 训练时间与 CPU 推理时间，且未计入调参，所以只表示量级，不是精确的成本对比。

**gap 的来源。** 剩余的 gap 由两部分组成。第一，在 LT 上，失败的回合（EXIT 或违约）贡献很少或没有 AR。第二，成功的回合往往比最优解多开一些低负载的 ECU。之前用旧网络做的诊断显示，几乎所有新开的 ECU 都是因为当前服务放不进任何已开 ECU 而被迫开启，而不是智能体主动选择，这同样指向更早的分组决策。结合 5.4 节的 EXIT 分析，这些结果表明，要进一步改进需要更好的长程规划，而不是更好的单步决策。

**局限。** (i) 学到的策略不保证最优；在最难的场景上，掩码仍有 1.38% 的实例 EXIT，实际部署时需要 ILP 或启发式作为后备。(ii) 只研究了 $N, M \in [10, 15]$ 的三个规模，且每个场景单独训练；虽然网络本身与 $N$、$M$ 无关，但尚未评估对更大或未见过的规模的泛化。(iii) DQN 上修复优于掩码的原因尚未解释。(iv) 计时在 CPU 上测得，每个变体只用种子 1 的模型；三个种子结构相同、每步计算量相同，预计推理时间一致。
