# 5.8 Discussion

> 大纲要点：设计成本在离线、规模限制、gap 来源。本节正文由作者撰写，以下为素材。

## 主结论

1. PPO-M（M + PPO + 关系感知 Transformer）0 违约，三场景平均相对 gap 4.38%，比 ILP 快 28×（LT 上约 48×），达到预定目标（至少一格三场景平均 gap ≤ 5% 且 Mask 最好）。
2. 策略：只有 M 能严格保证约束；R 只在死局违约；L、U 只靠奖励逐步减少违约，对 DQN/DDQN 尤其不友好。
3. 算法：PPO 在四种策略下都稳定（4.4–7.2%）；DQN/DDQN 只在 M、R 下有竞争力。
4. 场景：差距集中在 LT（M > N）；EQ/GT 上多个变体为 3–4%。

## 设计成本在离线

- Safe RL 的人工设计量比 ILP 多（MDP、奖励、约束策略、网络、超参数、训练数据），但全部在离线完成；在线每个实例只需一次 M 步前向推理（命题 2）。
- 训练成本一次性，可在大量同分布实例上摊销（命题 3）。不应写成"ILP 设计成本更高"。
- 来源：docs/ilp_vs_saferl.md 第 2–4 节。

## 规模限制

- 只有三个规模点（N, M ∈ [10, 15]）；正处在理论工作量曲线交点（N ≈ 8）之后不远，实测加速比为 1–2 个数量级（11.6–47.5×，按场景）。
- 未测更大 N、M 下的求解时间曲线与 RL 泛化能力。【空缺：更大规模实验未做】
- 网络对 N、M 无关（token 数可变），但不同规模的场景各自训练，未验证跨规模迁移。

## gap 来源

- 前期诊断（v4.x，MLP 时期，记忆 ar-gap-diagnosis / open-ecu-diag）：RL 与 ILP 的 gap 主要来自多开约 2 个低利用率的"尾巴" ECU；新开 ECU 中 97–99.6% 是被迫开启（当前服务无已开 ECU 可放），主动开启 ≤ 3%，因此 gap 源于更早的分组决策，而非开 ECU 的那一步。【注：该诊断基于旧网络，未在定稿模型上复测】
- Mask 的 EXIT（v6.0.2 诊断，`paper_contents/v6.0.2/exit_diag.md`，v6.0.0 Mask 模型，每种子 400 实例）：LT 上 EXIT 实例平均在第 4.3–4.5 步就已无可行完成（ILP 判定），而 EXIT 发生在第 11.9–12.1 步，潜伏约 7.3–7.7 步；一步必要条件只比 EXIT 早约 0.4 步察觉。即死局由早期决策造成、晚期才显现。
- 服务顺序：需求降序最好（v4.4.7 消融：降序 / 升序 / 随机平均 gap 10.1% / 12.6% / 13.4%，旧网络）。

## 局限

- RL 不保证最优，与 ILP 的比较不对等；
- M 在 LT 上仍有 1.38% 的 EXIT；
- R 在 DQN 上优于 M 的原因尚待解释；
- 计时在 CPU 单线程、24 进程并行下测得，只用种子 1 模型（三个种子网络相同）。
