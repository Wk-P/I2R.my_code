# 5.1 Setup

> 口径：定稿主表 v6.0.0-merge（`paper_contents/v6.0.0-merge/table_2d.json`），测试集 `data/testset_v6.0.4`；参数均已由 108 个 run 的 run.json 核对。

### 表 5.1  问题与数据

| 项目 | 设置 |
|---|---|
| 场景（N 个 ECU, M 个服务） | LT (10, 15)；EQ (10, 10)；GT (15, 10) |
| 容量 c_n / 需求 e_m | {50, 55, …, 195} / {10, 15, …, 95}，均匀随机 |
| 隐私冲突 | K = 10 个冲突集，服务两两冲突概率 p = 0.6 |
| 可行性 | 所有实例都经 ILP 求得最优解（Optimal） |
| 训练集 / 测试集 | 每场景 50,000 / 5,000 个实例，互不重叠；测试集固定，所有方法共用 |
| 基准 | ILP：Dinkelbach 迭代（容差 1e-6，平均 3.06 次），PuLP + CBC 单线程 |

### 表 5.2  对比方法（4 种机制 × 3 种算法 = 12 个变体）

| 机制 | 标记 | 约束处理 |
|---|---|---|
| Unconstraint | -U | 不做处理，违约只在终局奖励中体现 |
| Mask | -M | 屏蔽不可行 ECU；死局时只能选 EXIT |
| Repair | -R | 不可行动作改为 capacity-based best-fit（总容量最小的可行 ECU） |
| Lagrangian | -L | 每步奖励减 λ·c_t，λ 由对偶上升自动调整 |

算法为 PPO、DQN、DDQN，组合标记为 PPO-M、DQN-R 等。

### 表 5.3  MDP 与网络

| 项目 | 设置 |
|---|---|
| 放置顺序 | 服务按需求降序，一个回合 M 步 |
| 动作 | Discrete(N)；Mask 额外有 EXIT，为 Discrete(N+1) |
| 观测 | c、e、M×M 冲突矩阵、当前分配、步数 t（Lagrangian 另加 λ/(1+λ)） |
| 奖励（U / M / R：ar_pen） | 中间步为 0；回合全部合法完成时为 AR，否则为 −（未合法放置的服务比例） |
| 奖励（L：ar_obj − λ·c_t） | 终局奖励 ar_obj 为所有已执行放置（含违约放置）所在 ECU 的负载率平均，没有失败惩罚；违约只通过每步的 −λ·c_t 惩罚，c_t 为该步的容量违约数 + 隐私违约数 |
| 回合 | γ = 1，不提前结束，出现死局即记为违约 |
| 网络 | 关系感知 Transformer：d = 128，4 头，3 层，FFN 256，Pre-LN，4 类关系偏置，参数 450,227 |

### 表 5.4  训练超参数

| | PPO | DQN / DDQN |
|---|---|---|
| 并行环境数 | 40 | 12 |
| 学习率 | 3e-4 | 1e-3 |
| 批量 | 每次更新 20,480 步，minibatch 256 | 回放池 100k，batch 64 |
| 更新 | n_epochs：PPO-M 为 6，其余为 10 | 每 48 条新转移训练 1 次 |
| 其他 | GAE 0.95，clip 0.1，熵系数 0.005 | ε 在前 2M 步内从 1 线性降到 0，目标网络约每 492 步硬同步 |
| 共同设置 | 20M 步，种子 1/2/3，每个回合从训练池随机抽一个实例 | |
| Lagrangian | λ₀ = 0.001，Adam lr 0.035，目标 d = 0.001 次违约/回合，λ ≥ 0、无上限；PPO 每次 rollout 更新一次，DQN 每 1000 个回合更新一次 | |
| 软硬件 | Python 3.12，PyTorch 2.5.1，SB3 / sb3-contrib 2.7.1，Gymnasium 1.2.3；训练用 GTX 1080 Ti，计时用 Xeon E5-2660 v4 | |
