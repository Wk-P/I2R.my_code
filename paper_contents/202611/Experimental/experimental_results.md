## 2. Evaluation Metrics

- **测试模式**：用 20M 步的最终模型在固定测试集上做确定性推理（每步取 argmax），每个场景 5000 个实例。每个场景先对 3 个种子取平均，表中"平均"列为三个场景的算术平均；± 为种子间标准差。
- **AR**：只计合法放置的服务。
- **AR gap**：绝对 gap = ILP AR − AR；相对 gap = 1 − mean(AR) / mean(ILP AR)，在全部 5000 个实例上计算。下文未特别说明时，"gap"均指相对 gap。
- **违约率**：容量违约率、隐私违约率，各自统计出现至少一次该类违约的实例占比。两类可能同时出现在同一实例上，所以总违约率 ≤ 两者之和。
- **EXIT 率**（提前终止）：只有 Mask 有，指遇到死局时选择 EXIT 的实例占比。
- **时间消耗**：3×5000 个测试实例逐个计时，CPU 单线程（24 进程并行）。ILP 计时包含建模和全部 Dinkelbach 迭代；RL 计时为一个完整的确定性回合（reset、掩码、前向、step），用每个变体种子 1 的模型。加速比 = ILP 平均耗时 / RL 平均耗时。

## 3. Performance Comparison with ILP

### 表 5  PPO-M 与 ILP 的 AR

| EQ | 0.8624 | 0.8310 | 0.0314 | 3.64% ± 0.21% |
| GT | 0.9053 | 0.8756 | 0.0297 | 3.28% ± 0.08% |

分场景看，PPO-M 的加速比为 LT 47.5×、EQ 11.6×、GT 15.3×。

**分析要点**
1. PPO-M 的三场景平均 gap 为 4.38%，种子间标准差 0.17 pp，是 12 个变体中最低的，并且容量违约和隐私违约都为 0。
2. RL 每个实例耗时 46–53 ms，ILP 平均 1500 ms，加速比 28–32×。ILP 测试集上全部 15,000 个实例都求得 Optimal。
3. ILP 的耗时随问题规模增长得很明显：LT（M = 15）的均值是 EQ 的 6.4 倍，而且长尾严重（均值 3285 ms，中位数只有 1301 ms）。RL 的耗时只与步数 M 和 token 数成正比，LT 也只比 EQ 多约 1.5 倍，所以规模最大的 LT 上加速比也最大（约 48–55×）。
4. 各变体之间的耗时差异很小（≤ 7 ms）。PPO 略慢，是因为多算了一个价值头。

## 4. Comparison of Constraint Handling Strategies

### 表 7  三场景平均相对 gap（均值 ± 种子间标准差，越小越好）

| 机制 \ 算法 | PPO | DQN | DDQN | 行平均 |
|---|---|---|---|---|
| Mask | **4.38% ± 0.17%** | 7.17% ± 1.38% | **6.44% ± 1.19%** | **6.00%** |
| Repair | 7.15% ± 0.27% | **6.50% ± 0.55%** | 7.37% ± 1.14% | 7.01% |
| Lagrangian | 6.24% ± 1.01% | 12.51% ± 1.36% | 13.84% ± 0.50% | 10.86% |
| Unconstraint | 6.12% ± 0.28% | 24.97% ± 4.13% | 22.59% ± 2.37% | 17.90% |
| 列平均 | 5.97% | 12.79% | 12.56% | 10.44% |

（加粗为每列最好的值。）

**分析要点**
1. 按行平均，四种机制的排序为 Mask（6.00%）< Repair（7.01%）< Lagrangian（10.86%）< Unconstraint（17.90%）。只有 Mask 的违约率为 0。
2. 各算法内部的最好机制：PPO 是 Mask（4.38%），DDQN 是 Mask（6.44%），DQN 是 Repair（6.50%，Mask 为 7.17%）。
3. PPO 对机制最不敏感：四种机制都在 4.4–7.2% 之间，而且 PPO-U（6.12%）、PPO-L（6.24%）都略优于 PPO-R（7.15%）。DQN/DDQN 在 Lagrangian 和 Unconstraint 下明显变差（12.5–25.0%），说明只靠奖励信号处理约束时，基于值函数的算法学不好约束。
4. 对 DQN/DDQN 来说，"硬"机制（Mask、Repair）的 gap 比"软"机制（Lagrangian、Unconstraint）低约 5–18 pp。
5. Repair 在 DQN 上优于 Mask，原因尚未定论（属于当前主线的待答问题）。
6. 种子方差：PPO-M 最稳（0.17 pp）；DQN-U 方差最大（4.13 pp）。

**分析要点**
1. 难度排序为 LT > EQ > GT：12 个变体的平均 gap 分别是 14.93%、9.32%、7.07%。LT 的服务多、ECU 少（M > N），容量和冲突都最紧。
2. 每个场景的最好变体不同：LT 是 PPO-M（6.22%），EQ 是 DQN-M（3.54%），GT 是 DDQN-R（2.94%）。在 EQ 和 GT 上，最好的几个变体相差不到 1 pp（EQ 3.54–3.65%，GT 2.94–3.41%）。
3. 拉开差距的是 LT：PPO-M 比次好的 PPO-L 低 0.10 pp，比 DQN-M 低 7.35 pp。DQN/DDQN 在 LT 上的 gap 都在 10% 以上。PPO-M 能在三个场景平均上排第一，主要靠它在 LT 上明显领先。
4. LT 上 ILP 的耗时也最长（表 6），因此 LT 既是 RL 最难的场景，也是加速收益最大的场景。

**分析要点**
1. Mask 在构造上就不会违约：12 个变体中只有 Mask 的三个变体容量和隐私违约都为 0，符合"隐私是硬约束"的要求。它唯一的失败形式是遇到死局时选 EXIT，几乎只出现在 LT 上（1.38–3.87%）。
2. 所有测试实例都经 ILP 证明可行，所以 EXIT 和违约都意味着策略把自己引入了死局，而不是实例本身无解。
3. 在 LT 上，PPO-M 的 EXIT 率（1.38%）低于 PPO-R、PPO-L、PPO-U 的违约率（1.87–2.54%）。也就是说，加上掩码并没有让失败变多。
4. Repair 只在死局（没有可行 ECU 可以替换）时违约，违约以隐私违约为主（LT 上 2.4–6.2%）。在 p = 0.6 的高冲突密度下，死局主要是冲突造成的。
5. Lagrangian 把违约压到了较低水平（0.6–2.1%），但到 20M 步时 J_C 仍未降到目标 0.001，违约不为 0。
6. Unconstraint 的 DQN/DDQN 基本没有学会遵守约束：LT 上约 80% 的实例违约，几乎全是隐私违约。PPO-U 的违约率只有 0.75%，说明 PPO 仅凭 ar_pen 的终局负奖励就能学到大部分约束。
7. 违约实例上的放置不计入 AR，所以 Mask 以外的变体的 gap 已经包含了违约带来的 AR 损失。但它们是在"允许违约"的条件下得到的，与 Mask 的 gap 并不严格对等。

## 7. Discussion

1. **主结论**：PPO-M（Mask + PPO + 关系感知 Transformer）在 0 违约的前提下，三场景平均 gap 为 4.38%，速度比 ILP 快 28×（LT 上约 48×），达到预定目标（gap ≤ 5% 且 Mask 最好）。
2. **机制**：只有 Mask 能严格保证约束；Repair 次之（只在死局违约）；Lagrangian 和 Unconstraint 只能靠奖励逐步减少违约，并且对值函数类算法很不友好。
3. **算法**：PPO 在四种机制下都稳定（4.4–7.2%）；DQN/DDQN 只有在硬机制下才有竞争力。
4. **场景**：差距主要集中在 LT（M > N）。EQ/GT 上多个变体都在 3–4%，LT 是区分方法优劣的关键场景。
5. **局限**：
   - RL 不保证最优，与 ILP 的比较并不对等；
   - Mask 在 LT 上仍有 1.38% 的 EXIT；
   - Repair 在 DQN 上优于 Mask 的原因尚待解释；
   - 计时只用了种子 1 的模型，并且是在 CPU 单线程、24 进程并行的条件下测的。
