# 3.1 System Model

## 符号（m, n, e_m, c_n, C_k）

| 符号 | 含义 |
|---|---|
| N, M | ECU 数、服务数 |
| n ∈ {1, …, N} | ECU 下标 |
| m ∈ {1, …, M} | 服务下标 |
| c_n | ECU n 的容量 |
| e_m | 服务 m 的资源需求 |
| C_k，k = 1, …, K | 隐私冲突集；同一冲突集内的任意两个服务不能部署在同一 ECU |
| x_mn ∈ {0, 1} | 服务 m 是否部署在 ECU n |
| y_n ∈ {0, 1} | ECU n 是否启用 |

本文实验中：c_n ∈ {50, 55, …, 195}，e_m ∈ {10, 15, …, 95}，K = 10，任意两个服务冲突的概率 p = 0.6；场景 LT (N=10, M=15)、EQ (10, 10)、GT (15, 10)（见 5.1）。

## 原稿（保留，原 Problem Formulation / System Model）

论文通过一套机制迁移ILP目标到Safe RL算法，直接使用了ILP的原目标函数作为Safe RL的目标函数。而约束条件作为了专用的约束类程序放入Safe RL。因为ILP是根据全局信息计算，而Safe RL和RL都是步进计算，缺少全局信息，因此约束条件的判断在每一步的计算中都会进行。
为了避免贪心模式带来的影响，我们不再使用传统的MLP作为RL的神经网络，而是使用Transformer为基础的感知型网络结构来替代了MLP生成策略。
