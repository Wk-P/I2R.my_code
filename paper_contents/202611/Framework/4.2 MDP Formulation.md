# 4.2 MDP Formulation

服务按需求降序排列并重新编号，使 e_1 ≥ e_2 ≥ … ≥ e_M（相同需求保持原顺序）；第 t 步（t = 1, …, M）部署服务 t。γ = 1。

## State

环境给出原始状态 s_t：

| 部分 | 维度 | 含义 |
|---|---|---|
| c | N | 各 ECU 容量 |
| e | M | 各服务需求（按部署顺序） |
| A ∈ {0,1}^{M×M} | M² | 冲突图：A_{mk} = 1 当且仅当 m ≠ k 且同属某个 C_k |
| 分配向量 | M | 每个服务所在 ECU 编号（0 = 未部署） |
| t | 1 | 当前步 |
| λ/(1+λ) | 1 | 仅 Lagrangian |

维度：LT 266、EQ 131、GT 136（Lagrangian 各 +1）。完整信息、未归一化；特征构造在网络内完成（4.3）。

原稿（保留）：状态空间描述那些一大堆维度

## Action

$$
a_t \in \{1, \dots, N\}\ \ (\text{U / R / L}),\qquad a_t \in \{1, \dots, N, \text{EXIT}\}\ \ (\text{M})
$$

离散动作：为当前服务 t 选择一个 ECU。

可行性：第 t 步之前已部署在 ECU n 上的服务集合为 H_n，剩余容量 r_n = c_n − Σ_{m∈H_n} e_m。可行集

$$
\mathcal{A}_t = \{\, n : r_n \ge e_t,\ \text{服务 } t \text{ 与 } H_n \text{ 无冲突} \,\}
$$

违约指示（实际执行的 ECU 记为 ã_t）：

$$
v^{\text{cap}}_t = \mathbb{1}\big[r_{\tilde a_t} < e_t\big],\qquad
v^{\text{priv}}_t = \mathbb{1}\big[\exists\, m \in H_{\tilde a_t},\ \exists\, k:\ \{t, m\} \subseteq C_k\big],\qquad
c_t = v^{\text{cap}}_t + v^{\text{priv}}_t
$$

原稿（保留）：RL为了通常使用步进的方式进行决策，因此我们同样给agent制造了步进的动作空间，但是动作空间表示选择。每一步都在判断当前服务是否能够放置在这个ECU节点上。

## Reward

合法部署数 M_v = Σ_t 𝟙[c_t = 0]；AR 只计合法部署：

$$
\text{AR} = \frac{\sum_{t:\, c_t = 0} e_t / c_{\tilde a_t}}{|\{\tilde a_t : c_t = 0\}|}
$$

**U / M / R：ar_pen**（中间步为 0，T 为最后一步）

$$
r_t = 0\ (t < T),\qquad
r_T = R_{\text{term}} =
\begin{cases}
\text{AR}, & M_v = M\\[2pt]
-\left(1 - \dfrac{M_v}{M}\right), & \text{否则（含 EXIT）}
\end{cases}
$$

成功为正（0, 1]，失败为负 [−1, 0)。

**L：ar_obj − λ c_t**（标准 Lagrangian，见 4.5）

$$
r_t = -\lambda c_t\ (t < M),\qquad r_M = \text{AR}_{\text{obj}} - \lambda c_M,\qquad
\text{AR}_{\text{obj}} = \frac{1}{|\mathcal{E}_{\text{exec}}|} \sum_{n \in \mathcal{E}_{\text{exec}}} \min\!\Big(\frac{\sum_{t:\, \tilde a_t = n} e_t}{c_n},\ 1\Big)
$$

AR_obj 包含违约部署、没有失败分支，违约只由 λc_t 惩罚。

原稿（保留）：四种不同的策略和DQN，不确定怎么写；Lagrangian 方案会利用Lagrangian的方式进行不一样的Reward Function 计算

> 说明：奖励只与策略有关、与算法无关——PPO、DQN、DDQN 在同一策略下用同一奖励。

## Episode（死局即违约）

- 回合固定 M 步，**不因违约提前结束**（full episode）；违约的部署照样执行并记录。
- 死局：当前服务没有可行 ECU（𝒜_t = ∅）。U / R / L 仍须选一个 ECU，必然违约；M 只能选 EXIT，回合立即结束并给失败奖励 −(1 − M_v/M)，此时 M_v = t − 1。
- 所有测试实例都经 ILP 证明可行，死局只由前面的决策造成。

原稿（保留）：在所有的策略中，当出现违约时，Episode 会直接被终止，并且给予reward 相应的计算分数。例外的是在Action Masking 的策略上，因为要选择一个正确的动作输出，当完全没有可选动作时候，我们在动作空间中临时添加一个EXIT表示退出，并且同样给出惩罚。

> 核对：原稿"出现违约时 Episode 直接终止"与实际实现不符。定稿 108 个 run 均为 `--full-episode`：违约不终止，只有 Mask 的 EXIT 会提前结束回合。
