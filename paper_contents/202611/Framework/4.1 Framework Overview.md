# 4.1 Framework Overview

## 从 ILP 迁移了什么

| ILP 中的元素 | Safe RL 中的对应 |
|---|---|
| 目标 AR（3.2） | 终局奖励（4.2 Reward） |
| 决策变量 x_mn | 每步动作：为当前服务选择一个 ECU（4.2 Action） |
| C1 每个服务恰好部署一次 | 回合结构：按顺序每步部署一个服务，共 M 步 |
| C2 容量、C4 隐私冲突 | 每步判断可行集 𝒜_t，由四种约束处理策略处理（4.5） |
| C3 启用关联、y_n | 隐含：ECU 上部署了服务即为启用 |

ILP 一次性看全局，RL 逐步决策，所以约束判断在每一步都进行。

## ILP 的角色

ILP 只用于：(1) 筛选实例（全部为 Optimal，保证可行且最优值已知）；(2) 评估（AR_ILP 作为 AR gap 参照）。ILP 的最优解不作为训练标签，训练是 model-free 的 RL，不是监督学习。

迁移过程就是直接利用原ILP的优化目标公式，拆解其中的约束条件。把优化目标作为强化学习模型的奖励函数；约束条件利用不同的安全策略在强化学习模型中实现软惩罚或者硬惩罚。

原 3.1 System Model 原稿（按大纲属于本节）：论文通过一套机制迁移ILP目标到Safe RL算法，直接使用了ILP的原目标函数作为Safe RL的目标函数。而约束条件作为了专用的约束类程序放入Safe RL。因为ILP是根据全局信息计算，而Safe RL和RL都是步进计算，缺少全局信息，因此约束条件的判断在每一步的计算中都会进行。
