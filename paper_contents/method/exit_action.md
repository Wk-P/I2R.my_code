# EXIT 动作：定义与必要性

- 适用范围：Maskable（Mask PPO / Mask DQN / Mask DDQN），v4.3.8 起所有 Maskable 实验都使用；代码 `src/paper_rl/env.py`（`exit_action=True`）。
- 本文件只给定义、公式、反例和实验证据；正文叙述由作者撰写。

## 1. 定义

第 t 步放置服务 $s_t$（按需求降序），动作空间是 N 个 ECU 加一个 EXIT：

$$\mathcal{A} = \{1, \dots, N\} \cup \{\text{EXIT}\}$$

ECU j 的合法性（容量与隐私两个约束都满足）：

$$m_t(j) = \mathbb{1}\left[\, r_t(j) \ge d(s_t) \ \wedge\ \nexists\, s' \in H_t(j):\ (s_t, s') \in \mathcal{C} \,\right], \quad j = 1, \dots, N$$

其中 $r_t(j)$ 是 ECU j 的剩余容量，$d(s_t)$ 是服务需求，$H_t(j)$ 是 ECU j 上已放的服务，$\mathcal{C}$ 是隐私冲突对。

EXIT 的掩码：只有在没有任何合法 ECU 时才合法，

$$m_t(\text{EXIT}) = \mathbb{1}\left[\, \textstyle\sum_{j=1}^{N} m_t(j) = 0 \,\right]$$

因此每一步恰好满足以下二者之一：(a) 至少一个 ECU 合法、EXIT 被屏蔽；(b) 没有合法 ECU、EXIT 是唯一合法动作。

选 EXIT 后回合终止，奖励为失败奖励（ar_pen）：

$$R = \begin{cases} \text{AR}, & M_v = M \ (\text{全部合法放置}) \\ -\left(1 - M_v / M\right), & \text{EXIT}\end{cases}$$

$M_v$ 是 EXIT 之前已合法放置的服务数。

## 2. 必要性

### 2.1 死局在 ILP 可行的实例上也会出现

实例有可行解（所有实例都经 ILP 求出最优解），并不保证策略在任意部分放置之后仍有合法动作。最小反例（无隐私冲突，只看容量）：

| | 容量 / 需求 |
|---|---|
| ECU | $e_1 = 10$，$e_2 = 6$ |
| 服务（降序） | $s_1 = 6$，$s_2 = 5$，$s_3 = 5$ |

- 可行解：$e_1 \leftarrow \{s_2, s_3\}$，$e_2 \leftarrow \{s_1\}$。
- 策略的一条轨迹：$s_1 \to e_1$（合法，剩 4）；$s_2 \to e_2$（合法，剩 1）；$s_3$：$e_1$ 剩 4、$e_2$ 剩 1，都放不下，$m_3(j) = 0\ \forall j$，进入死局。

每一步都是合法动作，但前面的选择让后面无路可走。训练中这种情况确实大量出现（见 §3.1）。

### 2.2 不能把全 0 掩码交给 Maskable 策略

Maskable 策略的动作分布为

$$\pi_\theta(a \mid s_t) = \frac{m_t(a)\, e^{z_a}}{\sum_{a'} m_t(a')\, e^{z_{a'}}}$$

（实现上把非法动作的 logit 设为 $-\infty$）。若 $m_t \equiv 0$，分母为 0，分布无定义：采样、$\log \pi$、熵都是 NaN。Mask DQN 的 $\arg\max_{a: m_t(a)=1} Q(s_t, a)$ 同样是空集上的 argmax。所以必须保证每一步至少有一个合法动作。

### 2.3 三种兜底方式的比较

| 方式 | 死局时 | 执行的放置是否违反约束 | 进入训练的数据 |
|---|---|---|---|
| **EXIT（采用）** | 唯一合法动作 EXIT，回合终止，$R = -(1 - M_v/M)$ | 否：Maskable 执行的每个放置都合法 | 只有 $\pi_\theta(\text{EXIT} \mid s_t) = 1$ 的一步 |
| 掩码全开（v4.3.7） | $m_t \equiv 1$，策略在全部 ECU 中选一个并执行，继续到 M 步 | 是：执行的放置违反容量或隐私约束 | 策略在全是非法动作上的选择 |
| 环境随机放置 | 跳过策略，环境随机放一个 ECU，继续到 M 步 | 是 | 死局步不进入训练 |

隐私约束是本文的硬约束：后两种方式都会真的执行一个违反约束的放置 $x_{s_t, j} = 1$，得到的部署方案不满足 ILP 的约束集合，与硬约束的设定矛盾。EXIT 是唯一在死局时不执行违约放置的方式；其语义是「该部署请求放不下，拒绝 / 上报」。

### 2.4 EXIT 不污染策略梯度，同时给前面的步骤留下学习信号

死局时 EXIT 是唯一合法动作：

$$\pi_\theta(\text{EXIT} \mid s_t) = 1 \ \Rightarrow\ \nabla_\theta \log \pi_\theta(\text{EXIT} \mid s_t) = 0$$

这一步对策略梯度没有贡献（熵也为 0），不会把概率推向任何非法动作。失败奖励经价值函数和优势回传到前面的步骤（γ = 1）：

$$\hat{A}_k = \sum_{l \ge k} (\gamma\lambda)^{l-k} \delta_l, \qquad k < t$$

导致死局的早期选择得到负优势。$-(1 - M_v/M)$ 随 $M_v$ 增大而变轻，越晚陷入死局罚得越轻，奖励仍能区分「差一点放完」与「很早就卡住」。

## 3. 实验证据

### 3.1 死局在训练中的出现频率

v4.4.16（结构感知 Mask PPO，5 万实例池，10M 步，3 种子；训练时随机策略的 EXIT 率 = 1 − 成功率）：

| 场景 | 0–0.1M 步 | 0.1–1M | 1–5M | 5–10M |
|---|---|---|---|---|
| LT | 36.0–37.5% | 6.9–7.5% | 2.9–3.2% | 2.5% |
| EQ | 0.1% | 0.0% | 0.0% | 0.0% |
| GT | 0.0% | 0.0% | 0.0% | 0.0% |

LT 训练初期超过三分之一的回合进入死局，死局处理不是边缘情况，必须有兜底（§2.2）。测试（确定性策略）EXIT 率：LT 1.0–2.25%，EQ 0–0.25%，GT 0%。

### 3.2 EXIT 与「掩码全开、违约后继续」的对比

同一设置（MLP，1M 步，种子 1），只改死局处理：

| 场景 | 方式 | capacity 违约率 | privacy 违约率 | EXIT 率 | AR gap |
|---|---|---|---|---|---|
| LT | 掩码全开（v4.3.7） | 4.8% | 7.8% | — | 0.198 |
| LT | EXIT（v4.3.8） | 0% | 0% | 12.5% | 0.207 |
| EQ | 掩码全开（v4.3.7） | 0.2% | 0% | — | 0.141 |
| EQ | EXIT（v4.3.8） | 0% | 0% | 0.2% | 0.143 |
| GT | 掩码全开（v4.3.7） | 0% | 0% | — | 0.149 |
| GT | EXIT（v4.3.8） | 0% | 0% | 0% | 0.148 |

AR gap 在两种方式下相同（差异在单种子噪声内），但掩码全开在 LT 上有 4.8% / 7.8% 的测试实例违反容量 / 隐私约束；EXIT 下违约率恒为 0。即：EXIT 以不损失 AR 为代价换来了约束的严格满足。

## 4. 评估口径

- Maskable 的 capacity / privacy 违约率恒为 0，改报 **EXIT 率** = 选了 EXIT 的测试实例比例（部署失败率）。
- AR、ILP AR、相对 gap 只在未 EXIT 的测试实例上计算（同一批实例）。
