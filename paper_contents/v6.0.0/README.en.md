Generated by `src/scripts/report_v6_0_0_info.py`; every value is read from the code, the runs' results.json / run.json and the installed libraries and checked with assert -- no number is typed in. No training, no evaluation.

## Scope and checks

- Scope: the 108 runs of the summary page (/summary, `src/scripts/merge_2d_table.py`) = 12 cells × 3 scenarios (LT / EQ / GT) × 3 seeds (1, 2, 3).
- Within a cell every setting (reward, network, hyper-parameters, data, steps, ...) is asserted identical across runs; only the commit and batch differ (table below).
- Code consistency: the runs come from 5 commits. `git diff <commit> HEAD` over the training files (env.py, graph_net.py, graph_policy.py, graph_dqn.py, dqn_variants.py, train.py, config.py, vec_env.py) shows only renames (cap/req → c/e, i/j → m/n), the ar_obj reward and the feas_in switch added but unused by these runs (all of them are equivalent to feas_in=True), and new unused flags. For these runs' settings training behaves as the current code, which this description follows.
- Notation: service m (M of them), ECU n (N of them), demand e_m, capacity c_n, placement x_mn, ECU-in-use y_n. DDQN = Double DQN.
