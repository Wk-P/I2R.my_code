# 各算法伪代码

本文档给出 6 个算法各自的**核心决策/约束处理机制**级伪代码（区别于 `论文概要3.md` 第十三节已有的"整体实验管线"和"单 episode 通用逻辑"伪代码——那部分讲的是所有算法共享的外层流程，这里讲的是每个算法在约束处理方式上的具体差异）。

伪代码直接对应 `scenarios/lt/{算法}/env.py` 与 `run_all.py` 的真实实现（以 lt 场景为准；三场景机制是否完全一致见各节说明）。**本版本反映 `final_paper_experiments` 分支 tag `v4.1.0.2` 的最终定案状态**——即"死代码惩罚"审计、修复、消融、部分回退全部完成之后的代码。完整的排查过程见 `paper_contents/v4.1.0_changelog.md`，本文档只呈现最终结论。

## PPO（P3，无约束 baseline）—— 全程未改动

用 `stable_baselines3.PPO`（非 Maskable 版本），动作空间是对 N 个 ECU 的无限制离散选择；环境虽然实现了 `action_masks()`（容量维度），但 `run_all.py` 从未用 `ActionMasker` 包装环境、也未传给 `MaskablePPO`，因此掩码方法只是留存的接口，训练时完全不生效。

```
for t = 1..M:
    a_t ← policy.sample(all N ECUs)          # 无任何约束限制,包括容量在内
    cap_violated      ← remaining_vms[a_t] < svc[t].requirement
    conflict_violated ← has_conflict(a_t, t)
    # 违规只记录计数,不影响本步是否能执行、也不改变本步reward
    ru ← svc[t].requirement / initial_vms[a_t]
    total_ru += ru                            # 即使违规,ru照常计入AR分子
    执行放置(a_t, svc[t])                      # 强制执行,允许remaining_vms变负/冲突共存
if t == M:
    reward ← 终局AR分级奖励(见12.3式),violations>0则退化为valid_placed比例惩罚
返回 episode是否成功(=violations==0), 最终AR
```

**关键点**：约束是否被满足只体现在 info 字典和最终 success 判定里，不体现在单步 reward、不限制动作空间——这是刻意设计的"什么都不管"下限基线，用来衬托其余 5 种算法各自处理约束的方式。这是6个算法里**唯一从头到尾代码零变化**的一个（其余5个都在v4.1.0系列里动过非终端步reward，最终只有ppo_lagrangian回退）。

## PPO+Mask（P4，硬掩码）—— 唯一真正使用动作掩码的算法

用 `sb3_contrib.MaskablePPO` + `ActionMasker` 包装环境（已核实真实生效，不是留存接口）；env 提供 `action_masks()`，采样前把不可行动作的概率直接置零。

```
def action_masks(state):
    svc ← services[t]
    base_mask[j] ← (remaining_vms[j] >= svc.requirement) AND NOT has_conflict(j, t)   # 硬约束:容量+冲突
    if base_mask全False:
        return base_mask                       # 无路可退,交给环境事后判violation
    refined_mask[j] ← base_mask[j] AND NOT lethal_after(j)   # 一步前瞻,排除会导致未来无处安放的选项
    return refined_mask if refined_mask有True else base_mask

for t = 1..M:
    mask ← action_masks()
    a_t ← policy.sample(仅mask=True的ECU)      # 采样空间被硬性限制,不可行动作概率强制为0
    violated ← (mask全False时触发强制溢出兜底,选剩余容量最大的ECU)
    reward_t ← violation_penalty(-2.0,仅强制溢出兜底触发时非零) + shaping(默认关闭)
    执行放置(a_t, svc[t])
if t == M:
    reward ← 12.3式分级终局奖励(lt场景另含AR权重课程w,见12.4)
```

**v4.1.0变更**：`violation_penalty` 此前是死代码（算了没接入reward），现已接入。因为掩码已结构性防住了绝大多数违规（campaign结果：lt/eq/gt三场景 CapViol%=ConflictViol%=0.00%），这项修复实际只在强制溢出兜底那种极罕见情况下才有效果，**对整体表现影响可忽略**，修复前后数据基本一致。`eq` 场景没有强制溢出兜底分支，该项不适用，代码未改动。

**关键点**：约束处理发生在动作**采样之前**，是6种算法里唯一能做到"训练/部署阶段均理论上零违规"的方式，代价是需要能穷举可行动作集合，且一步前瞻本身是启发式近似。

## Lagrangian PPO（P5，ppo_lagrangian）—— 无掩码，纯惩罚约束，最终回退到"逐步奖励恒为0"

**不使用任何动作掩码**——`env.py` 里定义的 `action_masks()` 是死代码，`run_all.py` 训练的是普通 `PrunedPPO`（`stable_baselines3.PPO` 的子类，只做负advantage样本降权重，跟掩码无关），从未用 `ActionMasker`/`MaskablePPO` 包装。**这是设计意图，不是bug**：P5 的方法论意义就是"用惩罚/对偶变量代替掩码"处理约束，若也硬掩码就和P4没有区别了，"拉格朗日方法"这个对照组就没有存在意义。

```
初始化: λ ← LAMBDA_INIT, base_penalty ← 0.2, LAMBDA_LR, LAMBDA_TARGET, LAMBDA_MAX(=2.0或10.0,视场景)

# 环境内部(每一步):
for t = 1..M:
    a_t ← policy.sample(all N ECUs)               # 无掩码,策略可以自由选到违规ECU
    cap_violated      ← remaining_vms[a_t] < svc[t].requirement
    conflict_violated ← has_conflict(a_t, t)
    c_t ← 1.0 if conflict_violated else 0.0        # 冲突指示量(拉格朗日只管冲突,不管容量)
    cap_penalty      ← -2.0 if cap_violated else 0.0
    lagrange_penalty ← -(λ + base_penalty) * c_t
    match_gain       ← svc[t].requirement / initial_vms[a_t]
    total_ru += match_gain                          # 违规也照常计入AR分子(跟P3一致的口径)
    执行放置(a_t, svc[t])                            # 无任何纠正,原样执行
    reward_t ← 0.0    # ★最终定案:非终端步恒为0,不接入cap_penalty/lagrange_penalty/match_gain
if t == M:
    reward ← 12.3式分级终局奖励(violations==0判定含冲突+容量计数)

# 训练回调(LagrangeCallback,每隔LAMBDA_UPDATE_WINDOW个episode执行一次对偶上升,不受reward_t=0影响):
avg_viol ← 该窗口内episode冲突违规率的滑动平均
λ ← clip(λ + LAMBDA_LR * (avg_viol - LAMBDA_TARGET), 0, LAMBDA_MAX)
env.set_lambda(λ)
```

**⚠️ 这不是"没修完"，是三轮消融后的主动决策**（详见 `v4.1.0_changelog.md`）：

1. **v4.1.0**：把 `reward_t` 接成完整公式 `match_gain + cap_penalty + lagrange_penalty`（含正向利用率项）。结果：lt场景 success_rate $0.81\to0.52$，conflict_viol $0.18\to0.47$，明显变差；eq场景反而略微变好，gt基本不变。
2. **v4.1.0.1**：假设是 `match_gain` 跟终局AR项重复计入导致的，去掉它只留惩罚项 `reward_t ← cap_penalty + lagrange_penalty`。重新5M步×3种子测试：lt场景 $0.52\to0.54$，$0.47\to0.45$，**几乎没变化**，假设被推翻。
3. **v4.1.0.2（当前）**：确认问题不在match_gain，是"任何非零逐步奖励在这个无结构保护的环境里都会破坏PPO训练"（可能是惩罚量级 -2.0 加上自适应增长的λ，跟终局奖励量级(~M=15)相当，扰乱了GAE优势估计——对比`ppo_opt`的-0.1惩罚就小很多、且有repair兜底，同为PPO家族却是修复有效的）。**回退为 `reward_t = 0.0`，等同v4.0.0原始行为**。

**关键点**：容量、冲突都不阻止执行，$\lambda$ 的对偶上升是这四种约束机制里唯一维护真实对偶变量、按violation率做梯度式更新的方案，且**这个机制的运作完全不依赖per-step reward是否为0**——λ只看episode级违规率统计。严格来说是"硬约束都没有、纯靠训练本身学会规避+一个游离于reward之外的对偶调节器"的混合方案，不能笼统写成"拉格朗日处理全部约束"。

## Repair PPO（P6，ppo_opt，启发式修复兜底）—— v4.1.0修复效果最显著的算法

策略在完全无约束的动作空间上采样；若选择违规，环境内部立即用 best-fit 启发式**重新指派**一个可行 ECU 顶替原动作，再继续往下执行。

```
def best_fit_repair(svc_idx):
    svc ← services[svc_idx]
    valid ← {j : remaining_vms[j] >= svc.requirement AND svc_idx ∈ ecu_allowed[j]}
    if valid为空: return None
    return argmax_{j∈valid} (svc.requirement / initial_vms[j])   # best-fit:选剩余利用率最高的可行ECU

for t = 1..M:
    a_t ← policy.sample(all N ECUs)                # 无掩码,策略可以选任意ECU
    cap_violated      ← remaining_vms[a_t] < svc[t].requirement
    conflict_violated ← has_conflict(a_t, t)
    was_repaired ← False
    if cap_violated OR conflict_violated:
        a_repaired ← best_fit_repair(t)
        if a_repaired is None:
            返回 reward=-M, episode立即终止
        a_t ← a_repaired
        was_repaired ← True
        repairs += 1
    执行放置(a_t, svc[t])
    reward_t ← -0.1 if was_repaired else 0.0        # ★v4.1.0起接入,此前是死代码(算了没接线)
if t == M:
    reward ← 12.3式分级终局奖励(success = 全程未触发任何修复)
```

**v4.1.0变更效果（三场景一致改善，是这轮修复里最确定的正面结果）**：

| 场景 | conflict_viol_rate: v4.0.0→v4.1.0 | success_rate: v4.0.0→v4.1.0 |
|---|---|---|
| lt | 0.5425→0.1450（大幅下降） | 0.5005→0.5408 |
| eq | 1.0000→0.7208（明显下降但仍高） | 1.0000→1.0000 |
| gt | 1.0000→0.7692（明显下降但仍高） | 1.0000→1.0000 |

**关键点**：真正"零违规"的保证来自环境内置的修复兜底，不是策略学会了避让。补上 `-0.1` 的修复惩罚后，策略触发修复的频率显著下降（尤其lt场景），**但eq/gt场景依然维持在70%+的高位**——说明修复机制被利用（reward hacking）的问题**被缓解了，没有被消除**：eq/gt资源太宽松，成功"稳赚不赔"，-0.1这点惩罚相对终局奖励仍然太小，不足以让策略完全放弃依赖修复。这一发现（"补丁有效但不充分"）本身是论文可以引用的结论，比"完全没有惩罚"和"惩罚解决了一切"都更准确。

## DQN —— v4.1.0修复效果同样显著

标准 off-policy Q-learning，动作空间与 PPO 家族一致，无掩码、无修复。

```
初始化: replay_buffer, q_net, q_net_target ← copy(q_net)
for env_step = 1..TOTAL_STEPS:
    a_t ← epsilon_greedy(q_net, obs_t)
    # --- 环境内部(每一步) ---
    cap_violated      ← remaining_vms[a_t] < svc[t].requirement
    conflict_violated ← has_conflict(a_t, t)
    cap_penalty      ← -2.0 if cap_violated else 0.0
    conflict_penalty ← -2.0 if conflict_violated else 0.0
    ru ← 0.0 if 违规 else svc[t].requirement/initial_vms[a_t]   # 违规时不计入AR分子(跟P3不同)
    执行放置(a_t, svc[t])                                        # 强制执行,remaining_vms可能变负
    r_t ← cap_penalty + conflict_penalty   # ★v4.1.0起接入,此前恒为0(死代码)
    if t == M: r_t ← 12.3式分级终局奖励
    # --- gt场景特例:容量违规是立即硬终止,r_t = conflict_penalty ---
    obs_{t+1}, done ← ...
    replay_buffer.add(obs_t, a_t, r_t, obs_{t+1}, done)
    if step % TRAIN_FREQ == 0:
        batch ← replay_buffer.sample(BATCH_SIZE)
        target_q ← r + (1-done) * gamma * max_a' q_net_target(obs_{t+1}, a')   # 标准DQN:target网络自己选也自己评估
        loss ← smooth_l1(q_net(obs_t, a_t), target_q)
        梯度下降更新 q_net
    if step % TARGET_UPDATE == 0:
        q_net_target ← copy(q_net)
```

**v4.1.0变更效果（三场景一致改善）**：

| 场景 | success_rate: v4.0.0→v4.1.0 | conflict_viol_rate: v4.0.0→v4.1.0 |
|---|---|---|
| lt | 0.361→0.533 | 0.577→0.427 |
| eq | 0.660→0.763 | 0.332→0.230 |
| gt | 0.836→0.908 | 0.143→0.076 |

**关键点**：DQN/DDQN 是这套死代码bug里受益最直接的两个算法——因为它们既无掩码结构性保护、也无修复兜底，v4.0.0时完全没有任何逐步反馈，只能靠episode结束时那一次稀疏信号学习。补上密集的逐步惩罚后，虽然违规率仍然不算低（20-43%区间），但Q-learning的Bellman bootstrap能相对有效地把这个信号逐步传导回早期决策，三场景全部方向一致地改善。

## DDQN —— 与DQN机制相同，效果相近

继承 `stable_baselines3.DQN`，只重写 `train()` 方法里 target Q 值的计算方式（Double DQN, van Hasselt et al. 2016），环境侧（约束处理、reward公式）与DQN完全一致，是控制变量下唯一的差异点。

```
class DDQN(DQN):
    def train(gradient_steps, batch_size):
        for _ in range(gradient_steps):
            batch ← replay_buffer.sample(batch_size)
            best_actions ← argmax_a' q_net(obs_{t+1}, a')          # 用在线网络选动作
            next_q       ← q_net_target(obs_{t+1})[best_actions]   # 用target网络只评估该动作的价值
            target_q ← r + (1-done) * gamma * next_q
            loss ← smooth_l1(q_net(obs_t, a_t), target_q)
            梯度下降更新 q_net
        # 环境/reward/探索策略/replay buffer均与DQN共享,v4.1.0的cap_penalty+conflict_penalty
        # 接入方式完全相同
```

**v4.1.0变更效果**：三场景同样一致改善（success_rate: lt 0.351→0.465，eq 0.638→0.740，gt 0.881→0.925），幅度与DQN相近，DDQN在gt场景改善后甚至反超DQN。

**关键点**：DQN 用 `q_net_target` 同时完成"选动作"和"评估价值"，容易高估Q值；DDQN把两个角色解耦到在线/目标两个网络，抑制过估计偏差——这是两者唯一的代码级差异，其余（约束处理、reward、探索策略）完全共享。

## 六算法约束处理机制一览（v4.1.0.2最终版）

| 算法 | 动作空间是否受限 | 约束处理时机 | 训练/部署零违规保证 | v4.1.0死代码修复 |
|---|---|---|---|---|
| PPO (P3) | 否，全空间自由采样 | 无——只记录 | 无 | 不适用（无此类惩罚设计） |
| PPO+Mask (P4) | 是，采样前硬掩码(容量+冲突+一步前瞻) | 采样前 | 有（结构性，mask非全False时） | 已接入，影响可忽略（掩码本就防住违规） |
| Lagrangian PPO (P5) | 否，全空间自由采样 | 无——纯惩罚(概念上)，但**惩罚未接入reward** | 无 | **接入后测出负面效果，最终回退为reward=0** |
| Repair PPO (P6/ppo_opt) | 否，全空间自由采样 | 事后：环境内 best-fit 重新指派 | 有条件（修复失败时判负） | **已接入，三场景一致改善（效果最显著）** |
| DQN | 否，全空间自由采样 | 无——只记录+惩罚 | 无 | **已接入，三场景一致改善** |
| DDQN | 否，全空间自由采样 | 无——只记录+惩罚(与DQN共享环境) | 无 | **已接入，三场景一致改善** |

以上机制描述与 `论文概要3.md` 十二/十三节的公式/流程级伪代码、以及 `formula.md` 的完整LaTeX公式互为补充；完整的排查/消融/回退过程记录在 `paper_contents/v4.1.0_changelog.md`。
