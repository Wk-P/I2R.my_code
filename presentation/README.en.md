# Walkthrough index (v6.0.0)

Read in order. Each file covers one thing: intuition first, details second.

| # | File | Topic | In one line |
|---|---|---|---|
| 1 | [01_problem.en.md](01_problem.en.md) | The problem | Pack services into ECUs as full as possible, without exceeding capacity or co-locating conflicting services |
| 2 | [02_ilp.en.md](02_ilp.en.md) | The reference: ILP | A solver computes the optimum, our "full marks" |
| 3 | [03_environment.en.md](03_environment.en.md) | Turning it into a game | One service per step; the agent picks an ECU each step |
| 4 | [04_strategies.en.md](04_strategies.en.md) | 4 constraint strategies | What happens on a wrong choice: block / fix / penalize / ignore |
| 5 | [05_algorithms.en.md](05_algorithms.en.md) | 3 RL algorithms | PPO learns probabilities, DQN/DDQN learn scores |
| 6 | [06_network.en.md](06_network.en.md) | The network (Transformer) | Every ECU and service is a token; they look at each other, then each ECU gets a score |
| 7 | [07_training.en.md](07_training.en.md) | Training | 20M steps, 3 seeds; callbacks log and update λ |
| 8 | [08_results.en.md](08_results.en.md) | Results | Mask PPO is best: 4.38% below ILP on average, over 20× faster |

4 strategies × 3 algorithms = **12 variants**, all sharing the same environment (file 3) and network (file 6).

The formal, complete version is `paper_contents/v6.0.0/`; this folder only explains. All numbers come from there and from `paper_contents/v6.0.0-merge/`.
