# 4. 四种约束处理：智能体选错了怎么办

"选错"= 选了一个放不下（超容量）或有冲突的 ECU。四种做法：

| 变种 | 白话 | 会违约吗 |
|---|---|---|
| **Mask（掩码）** | 根本不让它选错：错的选项直接挡住 | 永远不会 |
| **Repair（修复）** | 让它选，选错了环境帮它改成一个对的 | 只在死局时 |
| **Lagrangian（拉格朗日）** | 让它选，选错就扣分，扣多少自动调 | 会，但越学越少 |
| **Unconstraint（不约束）** | 什么都不管，只在最后结算时吃亏 | 会 |

## Mask

- 每一步算出"合法 ECU"：剩余容量够 **且** 上面没有冲突服务。不合法的选项概率/分数直接压成负无穷，选不到。
- 死局时唯一能选的是 EXIT，选了就结束、给失败分。
- 所以 Mask 构造上**永远不违约**，最符合"隐私是硬约束"。

## Repair

- 智能体选了不合法的 ECU，环境替它换成"合法 ECU 里 e_m/c_n 最大的那个"，即 capacity-based best-fit：只看总容量 c_n，在合法 ECU 中选容量最小者，不看当前剩余容量。
- 训练数据里记的仍是智能体自己选的动作，它要自己慢慢学会别依赖修复。
- 死局时没得换，只能违约。

## Lagrangian

- 选什么就执行什么。每步记一个代价 c_t：超容量 +1，冲突 +1（0、1 或 2）。
- 每步奖励 = 目标分 − **λ × c_t**。λ 是"罚款单价"：
  - 违约多了 → λ 自动涨，罚得更狠；
  - 违约少了（低于目标 0.001 次/局）→ λ 自动降。
- λ 用 Adam 自动调（细节见第 7 篇），也会告诉网络（观测最后一维 λ/(1+λ)）。
- 它的目标分 `ar_obj` 和别人不同：所有放过的 ECU（含违约的）负载率取平均，**没有失败惩罚**，违约只靠 λ 来罚。
- 训练结束时 λ：PPO 约 1 ~ 2.4，DQN/DDQN 约 4.4 ~ 5.5。

## Unconstraint

- 不挡、不改、不额外罚，只用 `ar_pen`：有违约这局就算失败、拿负分。
- 是对照组，看"什么都不做"有多差。

## 一张图总结

```
智能体选了 ECU a
   │
   ├─ Mask：a 不合法？→ 根本选不到（死局只能 EXIT）
   ├─ Repair：a 不合法？→ 换成容量最小的合法 ECU（capacity-based best-fit）（死局则违约）
   ├─ Lagrangian：照放，违约就扣 λ×c_t，λ 自动调
   └─ Unconstraint：照放，最后违约就算失败
```
