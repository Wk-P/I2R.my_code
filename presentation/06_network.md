# 6. 网络：带关系提示的 Transformer

代码：`src/paper_rl/graph_net.py`（`GraphPolicyNet`）。12 个变种用的都是它。

## 为什么不用普通 MLP

MLP 把所有数字拼成一长串，"ECU 3 的剩余容量"和"服务 7 的需求"有什么关系，它得自己猜。
可我们的问题天然是"一组 ECU + 一组服务 + 它们之间的关系"，像一张图。
所以借用 Transformer：**把每个 ECU、每个服务当成一个"词"，让它们互相看**。

## 第 1 步：拆成"词"（token）

以 EQ（10 个 ECU、10 个服务）为例，一共 21 个词：

- **1 个全局词**：整体情况，4 个数：目前的 AR、还没放的服务占比、没放服务的总需求 / 总容量、剩余容量 / 总容量（Lagrangian 再加 λ）。
- **N 个 ECU 词**，每个 6 个数：容量、剩余空间、是否已启用、**能不能放当前服务**、已放了几个服务、负载率。
- **M 个服务词**，每个 5 个数：需求、是否已放、**是不是当前要放的**、有几个 ECU 能放它、和几个没放的服务冲突。

这些都由网络从原始观测自己算出来（`build()`），然后每个词变成 128 个数的向量。

## 第 2 步：互相看（注意力），做 3 轮

每个词看一遍所有其他词，再更新自己。例如：

- ECU 3 发现"当前服务和我上面某个服务冲突" → 知道自己不该被选。
- 服务 5 发现"能放我的 ECU 都快满了" → 这个信息会传给相关 ECU。

**关系提示**：我们直接告诉注意力哪些词之间有特殊关系，让它更容易注意到：

1. 两个服务互相冲突
2. 某服务放在某 ECU 上
3. 某服务和某 ECU 上的已有服务冲突
4. 某服务放得进某 ECU

每种关系有一组可学习的权重（一开始是 0，学出来多重要就多重要）。

每轮分 4 个"头"同时看（每个头可以关注不同的东西）；看完后每个词自己再加工一下（小前馈网络）。一共 3 轮。

## 第 3 步：打分

- 每个 ECU 词 → 同一个小网络 → **一个分数**。
- 全局词 → **EXIT 的分数**（只有 Mask 用）。
- 全局词 + 所有词的平均 → **V(s)**（只有 PPO 用）。

## 第 4 步：怎么用分数

- PPO：分数 → softmax → 概率。
- DQN/DDQN：分数就是 Q 值。
- Mask：不合法的 ECU 分数压成负无穷。

## 一张图

```
原始观测
   │  build()：算出每个 ECU / 服务的特征 + 4 种关系
   ▼
[全局] [ECU1 … ECUn] [服务1 … 服务m]     ← 每个变成 128 维
   │
   ├─ 注意力（+关系提示）→ 前馈   ┐
   ├─ 注意力（+关系提示）→ 前馈   ├ 3 轮
   ├─ 注意力（+关系提示）→ 前馈   ┘
   ▼
ECU 词 → 每个 ECU 一个分数    全局词 → EXIT 分数    全局+平均 → V(s)
```

## 数字对照表

| 术语 | 值 | 白话 |
|---|---|---|
| d | 128 | 每个词用 128 个数描述 |
| 头数 | 4（每头 32 维） | 分 4 组同时看 |
| 层数 | 3 | 互相看 3 轮 |
| 前馈 | 128→256→128，GELU | 看完后每个词自己加工 |
| Pre-LN | | 每轮先归一化，训练更稳 |
| 位置编码 | 无 | ECU 换个顺序，结果跟着换，不认编号 |
| 参数量 | 450,227（Lagrangian 450,355） | 约 45 万个可学习的数 |

**同一个网络能用在不同大小的场景**：词的个数随 N、M 变，网络参数不变。
