# Comparison of v0.0.1 and v0.1.0

## v0.0.1 (archive of the old experiment code, commit 65c0ea0)

- Tagged on 2026-06-24 as a baseline snapshot of the "old experiment code", commit message `archive: old experiment code as v0.0.1 baseline`.
- Rather mixed content, including:
  - project miscellany such as `README.md`, `.clauderc`, `.python-version`;
  - callbacks, evaluation tools and plotting scripts under `ecu_eq_svc_p/experiment/` (callbacks.py, eval_utils.py, plots.py, etc.);
  - `old-research-code/`: old aggregation scripts (aggregate_results.py, plot_aggregate.py), parallel run scripts (run_all_parallel.sh, etc.), logs and experiment reports (experiment_report*.md/html, experiments_cn_lt.md/html, etc.);
  - `old/reports_20260513/{eq,gt,lt}/`: historical reports per scenario eq/gt/lt (config.json, methods.md, parameters.md, reports.md, results.md);
  - raw result CSVs of each algorithm (ppo_mask, ppo_lagrangian, ppo_opt, ddqn, dqn) under several seeds (e.g. seed_4).
- Role: **a complete archive of the historical experiments**, code and reports mixed, with many outdated or exploratory scripts.

## v0.1.0 (cleaned-up core experiment code, commit a090f09)

- Also tagged on 2026-06-24, commit message `feat: v0.1.0 clean core experiment code`, which states:
  > Remove old archives, docs, aggregate scripts, frontend. Keep only ecu_{eq,gt,lt}_svc_p core algorithm files.
- Compared with v0.0.1: **753 files changed, 2007 lines added, 73669 lines deleted**, a large cleanup:
  - removed the whole historical archive and report directories `old-research-code/` and `old/reports_20260513/`;
  - removed the old aggregation/plotting/parallel-run scripts;
  - removed the frontend;
  - added/kept standard project configuration such as `pyproject.toml` and `requirements.txt`;
  - kept only the three core scenario directories `ecu_eq_svc_p/`, `ecu_gt_svc_p/`, `ecu_lt_svc_p/`, each with the same layout:
    - `problem1/` (environment definition env.py)
    - `problem2_ilp/` (ILP optimum: config + objects.py + optimal_solution/main.py)
    - `problem3_ppo/`, `problem4_ppo_mask/`, `problem5_ppo_lagrangian/`, `problem6_ppo_opt/` (PPO variants)
    - `problem_dqn/`, `problem_ddqn/` (DQN/DDQN baselines)
    - shared utilities: `run_utils.py`, `timer_utils.py`, `training_steps_config.py`
- Role: **the core algorithm code after cleanup**; the three scenarios (eq/gt/lt) have a fully symmetric structure, easy to reproduce and compare.

## Later changes (current main branch, commit 776ecb7)

On top of v0.1.0 another refactor followed: `refactor: reorganize into scenarios/ + shared/ architecture`,
merging `ecu_eq_svc_p / ecu_gt_svc_p / ecu_lt_svc_p` into `scenarios/{eq,gt,lt}/`,
and renaming the submodules of each scenario to clearer names (e.g. `problem3_ppo` → `ppo`, `problem_ddqn` → `ddqn`).
