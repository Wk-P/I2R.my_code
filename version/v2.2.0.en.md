# v2.2.0

## Background

The two rounds of experiments in v2.0.0/v2.1.0 (best-of-N sweep, self-imitation fine-tuning) all focused on
success_rate (can all 15 services be placed legally); AR (placement quality) was throughout
only a passively observed metric, never actually an optimization target. The root cause is the reward function —
[env.py](../scenarios/lt/ppo_mask/env.py) (the purely terminal sparse reward set up in v1.1.0):

```python
reward = float(self.M) if total_viol == 0 else -float(self.M)
```

**As long as it succeeds (zero violations), the reward is always +M, whether AR is 0.55 or 0.95.** PPO's
gradient never contained the signal "among successful placements, move towards higher AR" —
success_rate could be pushed up by best-of-N / self-imitation because they directly
optimize the binary "success" target; but AR stayed at 0.61~0.65 (vs ILP optimum
0.7213) not because it could not be learned, but because **the reward function never asked for it**.

Self-imitation (v2.1.0) amplified the problem: sampling "stops at the first successful trajectory"
without filtering by AR, so the imitated trajectories have unknown quality.

## Change in this version: AR enters the reward, violations stay hard constraints

Implemented according to the user's two explicit requirements:
1. **AR is the target to improve** — not just a passive metric.
2. **Both constraints (capacity/conflict) stay zero-tolerance** — they must not be broken in pursuit of AR.

The terminal reward of `scenarios/lt/ppo_mask/env.py::step()` becomes:

```python
reward = float(self.M) * self.ar if total_viol == 0 else -float(self.M)
```

- With zero violations: the reward is proportional to AR (`M*AR`), so the gradient distinguishes "a success with AR=0.55"
  from "a success with AR=0.90" instead of giving the same +M as before.
- With violations: the reward stays `-M`. Since AR∈(0,1], `M*AR <= M`, and
  `-M < 0 < M*AR` holds for any AR, so **the priority "any success beats any violation"
  is preserved mathematically**, with no extra weights needed to balance the two objectives.
- Action masking (the hard constraint) is unchanged; capacity/conflict violation rates should still always be 0
  — this reward only affects the rare edge case of "a forced fallback because the mask is all False",
  not the fact that violations cannot happen on the normal path.

## Scope and validation

- Only `lt/ppo_mask/env.py` changed; the reward of the `eq`/`gt` scenarios and the other algorithms
  (`ppo_lagrangian`/`ppo_opt`/`dqn`/`ddqn`) is unchanged.
- **This is a fundamental change of the training objective; it cannot be validated by fine-tuning and needs a full 5M-step rerun** —
  `run_all_bc.py` is rerun with the standard `src/scripts/resume_scenario.sh lt ppo_mask_bc` flow (not a side
  script), so that `results.json` is written correctly and
  the dashboard tracks progress normally, unlike the self-imitation experiments that ran outside the standard
  pipeline.
- Started with `TRAIN_SEED=42` (the same train/test split as all previous lt/ppo_mask experiments); when it finishes, compare:
  - whether AR really moves from 0.61~0.65 towards the ILP's 0.7213;
  - whether success_rate (N=1/N=8/best-of-N=1024) is affected by the reward target changing from purely
    binary to "binary + quality" (in theory it should not drop, because the priority of the violation penalty
    is unchanged, but this must be measured).
