# v0.2.0

## Background

The evaluation of v0.1.1 only reports the mean AR (resource utilization) and one combined `viol_rate` (capacity + conflict violations added into a single rate), missing two key pieces of information:

1. Of the 40 test scenarios, **what share has all M services placed with zero violations** (not a partial share, but a binary "fully successful" verdict);
2. capacity and conflict violations are two different kinds of constraint; combining them into one number hides which one is holding things back.

## Changes in this version

### Backend (18 `scenarios/{eq,gt,lt}/{ppo,ppo_mask,ppo_lagrangian,ppo_opt,dqn,ddqn}/run_all.py`)

- `run_episodes()` adds a verdict for every test episode:
  ```
  success = (all M services placed) AND (capacity violations == 0) AND (conflict violations == 0)
  ```
- `results.json` / `summary.csv` gain three fields replacing the old combined `viol_rate`:
  - `success_rate`: share of the 40 test scenarios that are "fully successful"
  - `cap_viol_rate`: share of scenarios with a capacity violation
  - `conflict_viol_rate`: share of scenarios with a conflict violation
- The existing `cap_viol_total` / `conflict_viol_total` (cumulative counts of violation events) are kept unchanged.

### Pre-existing bugs fixed along the way

- `run_episodes()` of `eq/ppo_opt` and `gt/ppo_opt` referenced undefined `valid_placed_list`/`ecus_used_list` and raised `NameError` at run time; also the downstream CSV header (7 columns) did not match the number of values written in the ILP row (9).
- `cap_viol_total` of `lt/dqn` and `lt/ddqn` wrongly counted "episodes with any violation" instead of the real number of capacity-violation events (the `eq`/`gt` versions were already right).

### Backend API (`app/backend/main.py`)

- Removed `_viol_rate()`, which pieced together a single violation rate by probing several field names.
- `_row_from_run()` exposes three separate fields: `test_success_rate`, `test_cap_viol_rate`, `test_conflict_viol_rate`.

### Frontend (`ExperimentTree.vue`, `RunDetail.vue`)

- Neither the list page nor the detail page shows the combined "Viol Rate" any more; instead three side-by-side columns "Success Rate" / "Cap Viol Rate" / "Conflict Viol Rate" (the detail page also keeps the total violation events).
- Success rate ≥ 99.9% is shown in green, otherwise in a warning colour.

## Notes

- Older `results.json` files under `results/` (from v0.1.1 and earlier) have no `success_rate` etc.; the frontend shows `—`; rerun training/evaluation with this version's code to see the new metrics.
- The `VERSION` constant (`shared/paths.py`) goes from `0.1.1` to `0.2.0`; newly trained model files carry this version number.
