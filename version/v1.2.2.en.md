# v1.2.2

## Background

In the lt scenario (M=15, utilization 64%) the success_rate of ppo_mask/ppo_lagrangian is only 32.5%~42.5%, clearly below eq/gt (lower utilization, 100% success). The analysis: the trained policy is an **online, non-backtracking** decision maker — services arrive one by one and an ECU choice cannot be undone; such problems have a theoretical online-vs-offline competitive-ratio lower bound (no online algorithm can always match the offline optimum in the worst case). The ILP succeeds 100% because it is an offline global solver, not because its constraints are looser.

## Changes in this version

### best-of-N random resampling at evaluation

`scenarios/{eq,gt,lt}/{ppo_mask,ppo_lagrangian}/{run_all.py,run_all_bc.py}` (12 files):

- `run_episodes()` gains an `n_samples` argument: each test scenario is run up to `n_samples` times independently with **random sampling** (instead of `deterministic=True`), stopping as soon as one attempt fully succeeds (`valid_placed==M`; ppo_lagrangian also requires zero violations); if all attempts fail, the best one is kept (success first, then most valid_placed, then highest AR).
- New `attempts` field: how many attempts each test scenario actually used (1~n_samples), written to `attempts_mean` in `results.json` and printed in ppo_mask's console output.
- Each scenario's `ppo_mask/config.py` and `ppo_lagrangian/config.py` gains `EVAL_BEST_OF_N = 8` (default retry limit 8).
- The `ppo_policy` closure changes from `deterministic=True` to `deterministic=False` — independent attempts only make sense when actually sampling from the policy distribution (a deterministic policy gives the same result every time).

### Validation (lt/ppo_mask, reusing the trained model of v1.2.1 exp_id=eb6ed7aa, no retraining)

| | single deterministic (v1.2.1) | best-of-8 (this version) |
|---|---|---|
| success_rate | 42.5% | **65.0%** |
| mean attempts | 1 (fixed) | 4.275 |

This confirms that "online, non-backtracking" is indeed one major cause of lt's low success rate — the same model, without retraining, gains 22.5 percentage points just from independent retries. 35% of the scenarios still fail within 8 attempts, so it is not the only cause; structural difficulty driven by tightness / share of large items remains.

### Version number

- `CURRENT_VERSION` in `src/shared/version_config.py` goes from `1.2.1` to `1.2.2`.

## Notes

- best-of-N only changes the evaluation, not training or the model, so trained historical models can be re-evaluated directly (as in the validation above) without rerunning `model.learn()`.
- N=8 is an initial default and has not been tuned; if the gain keeps growing with N, N can be increased (evaluation cost grows linearly with N; training time is unaffected).
- Only `ppo_mask`/`ppo_lagrangian` are covered; `ppo`/`ppo_opt`/`dqn`/`ddqn` do not have the same best-of-N evaluation logic yet.
