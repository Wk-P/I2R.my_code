# v1.2.3

## Background

v1.2.0 reduced the global `TOTAL_STEPS` from 5M to 2M because the training curve (episode AR) at the time levelled off within a few hundred thousand steps. But that AR curve was misleading — the lt/ppo_mask training curve from v1.2.2 ([training_curve.png](../results/paper-verfication/lt/ppo_mask/67b069d5_bc/training_curve.png), exp_id=67b069d5), the first to plot the `valid_placed` curve added in v1.2.0 (the true number of legal placements, excluding the forced-overflow fallback), showed that **while the AR curve was flat, the valid_placed curve was still clearly rising at the 2M-step cutoff and had not converged**, with a training instability around 1.4M steps (a sudden drop and recovery). So "5M steps are unnecessary, 2M are enough" only holds for eq/gt (both at 100% success_rate with 2M steps), not for a high-utilization (64%) scenario like lt — 2M steps cut it off while valid_placed was still climbing.

## Changes in this version

### Training steps overridden per (scenario, algorithm); lt back to 5M steps

`shared/training_steps_config.py`:
- New override table `SCENARIO_TOTAL_STEPS: dict[(scenario, algo), steps]`, taking precedence over the existing per-algorithm table `PROBLEM_TOTAL_STEPS`;
- `get_total_steps(problem_name, scenario=None)` gains a `scenario` argument: it first looks in `SCENARIO_TOTAL_STEPS`, then falls back to the per-algorithm lookup;
- Current overrides: `("lt", "ppo_mask")` and `("lt", "ppo_lagrangian")` → `5_000_000`; eq/gt are not in the table and keep the global default `2_000_000`.

`scenarios/{eq,gt,lt}/{ppo_mask,ppo_lagrangian}/config.py`:
- `TOTAL_STEPS = get_total_steps("ppo_mask")` becomes `get_total_steps("ppo_mask", scenario=ROOT.parent.name)` (likewise for `ppo_lagrangian`), passing the scenario name (eq/gt/lt, from the directory structure `ROOT.parent.name`) so that the override table takes effect.

Check:
```
eq/ppo_mask TOTAL_STEPS = 2000000
gt/ppo_mask TOTAL_STEPS = 2000000
lt/ppo_mask TOTAL_STEPS = 5000000       # restored
lt/ppo_lagrangian TOTAL_STEPS = 5000000  # restored
```

### Version number

- `CURRENT_VERSION` in `shared/version_config.py` goes from `1.2.2` to `1.2.3`.

## Notes

- When this version was released, the exp_id=67b069d5 batch (lt/ppo_mask finished 2M steps, lt/ppo_lagrangian still training, both on the 2M-step setting) was already running; these processes started under the old setting are not affected and finish at 2M steps, keeping the batch internally consistent (no batch with different step counts for lt and eq/gt). lt results at 5M steps come with the next run of `scripts/run_current_version.sh`.
- Only `ppo_mask`/`ppo_lagrangian` (the two algorithms in the current experiments) are covered; `ppo`/`ppo_opt`/`dqn`/`ddqn` are not wired into `SCENARIO_TOTAL_STEPS` yet.
- If lt's valid_placed curve still does not converge at 5M steps, consider more steps or a structural training-side change (reward shaping / curriculum learning) rather than endlessly adding steps.
