# v1.2.1

## Background

After running v1.2.0 (2M steps, exp_id=5f06588b, eq/gt/lt × ppo_mask/ppo_lagrangian) it turned out that `ar_mean`/`ar_std` had always averaged **successful and failed episodes together** — in `run_episodes()`, whether or not a test scenario reached `valid_placed == M` (all placed legally), its last-step AR was put into the `ars` list and averaged. The ILP's AR, however, is always the value of a "fully successful" solution (the ILP only outputs feasible solutions and never stops halfway). They are not the same statistic, and computing the gap between `AR_RL` and `AR_ILP` directly is misleading — especially on lt (success_rate only 32.5%~42.5%), where the gap is pulled down/up by the partial AR of many failed episodes, hiding the real difference in solution quality.

## Changes in this version

### AR excludes failed episodes

`scenarios/{eq,gt,lt}/{ppo_mask,ppo_lagrangian}/{run_all.py,run_all_bc.py}` (12 files):

- Right after `run_episodes()` returns, `ppo_res["ars"]` is filtered with the `success` mask, keeping only successful episodes with `valid_placed == M` (for ppo_lagrangian also `cap_v==0 and conflict_v==0`);
- Everything that uses `ppo_res["ars"]` afterwards — console output, `ar_mean`/`ar_std`, `summary.csv`, `results.json`, box plots — then automatically counts only successful episodes, with no separate changes needed;
- If an evaluation has success_rate=0% (possible in theory for unmasked algorithms), a warning is printed and `ar_mean`/`ar_std` are recorded as NaN instead of silently using an empty array / 0.

### Version number

- `CURRENT_VERSION` in `src/shared/version_config.py` goes from `1.2.0` to `1.2.1`.

## Notes

- This version only changes how AR is aggregated; reward, env, training hyper-parameters and steps are unchanged (still the 2,000,000 steps set in v1.2.0).
- Historical results (including the v1.2.0 batch exp_id=5f06588b) use the old aggregation and **should not be compared directly with AR numbers from this version on** — especially on the low-success lt scenario, where the old AR gap is clearly optimistic. A rerun is needed for comparable data.
- Only `ppo_mask`/`ppo_lagrangian` (the only two algorithms in the current experiments) are covered; `run_all.py` of `ppo`/`ppo_opt`/`dqn`/`ddqn` has the same "AR over successes and failures" pattern, not fixed yet; comparison experiments with these algorithms later need the same patch.
